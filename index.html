Five questions, five answers. Each one points to work I built.

1. Tell us about a problem you couldn’t leave alone. What did you build to fix it?

In Intensity-Modulated Radiation Therapy (IMRT) planning, balancing precise tumor radiation coverage against non-target organ safety creates computationally prohibitive optimization problems. Standard nuclear-norm minimization techniques for constraining fluence-matrix ranks were too memory-intensive for large clinical datasets like PortPy. I couldn't leave this efficiency trade-off unresolved, so I designed a convex optimization pipeline that introduced a novel spectral regularizer as a computationally lightweight surrogate for nuclear-norm constraints. Formulated using CVXPY on PortPy clinical datasets, this method strictly enforced critical clinical dose bounds (PTV ≥60 Gy, esophagus ≤45 Gy, spinal cord ≤30 Gy) while significantly reducing matrix rank and memory overhead without degrading beamlet quality or plan delivery safety.

2. Tell us about a time you had to understand an unfamiliar system that wasn’t behaving as expected. How did you get to the bottom of it?

During my internship at Daiichi Sankyo, I built an enterprise Master Data Management (MDM) tool combining OpenSearch vector retrieval, Neo4j graph storage, and LLM candidate matching to resolve entity relationships across massive pharmaceutical datasets. During pipeline execution, candidate generation began silently dropping obvious entity matches. Instead of making blind code changes, I systematically investigated the data boundary. I traced the query vectors directly inside OpenSearch indices to evaluate distance metrics, then isolated the execution of Cypher graph traversal rules in Neo4j. By asking targeted questions about how entity canonical keys were being propagated during incremental updates, I pinpointed the root cause: edge cases in state propagation across disconnected graph clusters. Refactoring the Union-Find canonicalization logic resolved the issue and restored 100% graph lineage traceability.

3. Describe a real coding task where AI tools helped you move faster. Where did you have to step in and think for yourself?

When building AdaptAlloc, a contextual bandit framework designed to adaptively route video frames between YOLOv8 (low-energy) and RT-DETR (high-accuracy), I used AI tools to accelerate drafting PyTorch frame loaders, Docker container scripts, and Streamlit benchmarking dashboard boilerplate. However, human intervention was critical when engineering the 9-dimensional state vector (measuring Shannon entropy and detection confidence) and designing the REINFORCE policy reward function. Generative AI suggestions initially produced naive reward structures that maximized object detection accuracy while ignoring compute latency and frame rate degradation. I stepped in to mathematically define a customized multi-objective trade-off function balancing energy consumption, inference speed, and mAP, ensuring the policy learned real-world real-time performance constraints.

4. Describe the extent to which you have experience with production systems.

At Daiichi Sankyo, I architected and deployed production-grade Retrieval-Augmented Generation (RAG) pipelines using OpenSearch vector retrieval, hierarchical chunking, reranking models, and FastAPI backend microservices. The system automated document review across 2,000+ enterprise files, reducing review turnaround time by over 95% (from 2 weeks down to 4 hours) while maintaining strict context accuracy. My production experience spans containerizing workloads with Docker, building low-latency REST APIs, optimizing LLM inference costs, and deploying computer vision models in real-time inference environments.
